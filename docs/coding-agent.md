# 编码 Agent 与工作区

主模型可对实现功能、修复问题、重构、写测试和运行验证等编码任务自主多步推进：先用只读工具理解项目，再按需修改、运行验证并检查结果，直到任务完成或遇到无法解决的问题。单条消息内最多连续调用工具 20 轮；点击“停止”会取消请求并中止正在执行的 Shell 命令。

完整工具清单见 [Skills 说明](skills.md)。本页聚焦编码工作流、工作区范围和安全边界。

## 双工作区

- **永久工作区**：长期存在的目录。默认是应用工作目录，也可在用户明确告知路径后切换。Git 仅在永久工作区启用。
- **临时工作区**：`%TEMP%\prana-scratch\`，应用启动时创建，系统或用户清理时可能被删除。需要保留的产物应使用 `transfer_workspace_file` 复制到永久工作区。

工作区路径由应用管理；工具不提供任意文件系统访问。每次工作区读取、写入、文件转移、切换以及 Shell 操作都须经操作审查模型批准。审查模型未配置、拒绝或返回无效结果时，操作不会执行。

## 项目与文件工具

- `get_project_structure` 查看项目目录结构；`search_workspace_files` 按文件名或文件内容搜索。会忽略常见缓存、构建和依赖目录，并限制扫描和返回结果。
- `read_git_repository` 只读查看 Git 状态、日志、差异或分支；不会暂存、提交、推送、切换分支或修改文件。
- `write_workspace_file` 创建文件，或在明确指定 `overwrite=true` 时覆盖已有文件。
- `edit_workspace_file` 按精确字符串修改已有文件；默认要求匹配位置唯一。
- `transfer_workspace_file` 在永久工作区和临时工作区之间复制文件；目标已存在时须显式设置 `overwrite=true`。
- `switch_workspace` 将当前会话的永久工作区切换到用户指定的已存在目录。

以上操作受路径约束。工作区读写及 Git 操作都需要操作审查；用户请求须明确且与具体目标相符。

## 终端与 Shell

`run_terminal_command` 只允许有限的只读目录/文件查询：位置查询、列目录、读取小型文本文件。单文件最多 64 KB；不支持脚本、命令链、写入或任意命令。访问工作区外路径需要用户明确授权。

`run_shell_command` 在所选工作区运行一条 PowerShell 命令，适用于 lint、test、build 和验证。`command`、`description` 必填；`timeout_seconds` 最长 300 秒；`workdir` 为工作区相对子目录；`workspace` 可选 `permanent` 或 `scratch`，默认永久工作区。stdout 和 stderr 分别截断到 16 KB，超时会返回 `timed_out=true`。

Shell 命令由当前 Windows 账户执行，可能改变系统状态；程序不提供命令白名单。删除、格式化、`git push`、`iex` 等危险命令应由审查模型从严判断。只应在信任当前 AI 服务时授权。

## 操作审查

操作审查模型会收到用户请求及操作参数，并必须明确批准相应操作。以下操作需审查：

- 项目/工作区读取、Git 读取、工作区写入、文件转移和工作区切换。
- 只读终端查询和 PowerShell Shell 命令。
- 桌面控制、媒体发送/生成、加入 Minecraft 服务器以及创建 Minecraft 自定义技能。

各类操作具体权限不同，审查通过不代表工具可超出其路径、参数或功能限制。模型配置和审查模型说明见[模型与配置](configuration.md)。
